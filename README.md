# TwinShip Ontology Repository

Welcome to the TwinShip Ontology repository! This project provides a modular, extensible ontology for the TwinShip project, supporting semantic interoperability, data integration, and knowledge representation in the maritime domain.

## Repository Structure

- `model/` — Main ontology files (core, vocabularies, individuals, external imports)
- `docs/` — Documentation, diagrams, and usage examples
- `tools/` — Scripts and tools for ontology validation and management
- `tests/` — SHACL shapes, SPARQL queries, and other validation resources
- `examples/` — Example data and usage scenarios

## Getting Started

### Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/twinship-eu/twinship-ontology.git
cd twinship-ontology

# 2. Run setup script (installs uv if needed and sets up dependencies)
./setup.sh

# 3. Generate complete website (documentation + visualization)
./scripts/generate_website.sh

# 4. View the result
open docs/website/index.html
```

### Explore the Ontology

- **Foundation**: [model/twinship-base.ttl](model/twinship-base.ttl) - Base classes and properties
- **Modules**: [model/modules/](model/modules/) - Domain-specific modules (vessel, weatherconditions, etc.)
- **Complete Ontology**: [model/twinship-core.ttl](model/twinship-core.ttl) - Aggregate importing everything

**Note**: The ontology uses OWL restrictions rather than rdfs:domain assertions to avoid unwanted inferences. For visualization, a domain/range version is automatically generated by the build scripts.

### Generate Documentation & Visualization

Generate complete website with WIDOCO documentation and WebVOWL visualization:

```bash
# Generate everything (documentation + visualization + landing page)
./scripts/generate_website.sh

# Start local web server
./serve_website.sh

# Or open directly
open docs/website/index.html
```

The landing page provides links to:
- **WIDOCO Documentation** - Comprehensive HTML documentation with diagrams and cross-references
- **WebVOWL Visualization** - Interactive force-directed graph visualization

**What gets generated:**
- `build/twinship-core-complete.ttl` - All modules merged
- `build/twinship-core-complete-viz.ttl` - Visualization-friendly version (domain/range)
- `build/twinship-core-complete-docs-viz.ttl` - Documentation version
- `docs/website/documentation/` - WIDOCO-generated HTML documentation
- `docs/website/visualization/` - WebVOWL interactive visualization
- `docs/website/index.html` - Landing page

### Ontology Statistics

A summary of the current ontology metrics (classes, properties, and imported ontologies) is maintained in [STATISTICS.md](STATISTICS.md).

Regenerate it at any time after modifying or extending the ontology:

```bash
uv run python scripts/generate_stats_table.py
```

This reads from `build/twinship-core-complete-docs-viz.ttl` (produced by the full build pipeline) and writes `STATISTICS.md` to the repository root. Run the full build first if the ontology has changed:

```bash
./scripts/generate_website.sh
uv run python scripts/generate_stats_table.py
```

### Workflow testing
Currently, Deployment workflow only supports deployment to Hostinger.
The **[deployment workflow](.github/workflows/deploy.yml)** can be tested locally using [act](https://github.com/nektos/act).
The workflow will default to skipping the deployment step when running using act, or if the `DRY_RUN` environment variable is set to `true`.

```bash
# test workflow locally 
act

# test workflow locally, excluding deployment step explicitly  
act --env DRY_RUN=true
```

Because Act runs inside an isolated Docker container, it cannot be used to test the deployment step, which attemps to ssh into a remote host and deploy the ontology using rsync. 

To test the deployment step, use the test-hostinger-deployment.sh script.
This is not a reliable way to test the deployment step, as hostinger will reject a lot of ssh origins, so you are not guaranteed to be able to connect. Using a mobile hotspot appears to be a working solution.
```bash
# The following variables need to be set in the environment for the script to work
# SSH_KEY - Your SSH key
# SSH_USER - Your Hostinger SSH username
# SSH_HOST - Your Hostinger SSH host IP
# SSH_PORT - Your Hostinger SSH port
# DEPLOY_PATH - The path on the remote host where the ontology website should be deployed
./scripts/test-hostinger-deployment.sh
```
